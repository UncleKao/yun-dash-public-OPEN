# 自訂分頁說明書

「自訂」分頁讓你**不用寫程式**，只要在設定檔 `config.json` 裡寫幾行文字，就能把自己 Home Assistant（以下簡稱 HA）裡的資料排成卡片：
目前的溫度、過去一天的用電折線圖、所有插座的功率列表……想看什麼自己組。

這份說明書是寫給**沒寫過程式的人**的，照著做、複製範例、換成自己的實體名稱就行。

## 1. 能做什麼、不能做什麼

**能做的（全部是「讀取並顯示」）：**

| 卡片 | 用途 | 例子 |
|---|---|---|
| `value` | 顯示一個或多個實體的**目前值**（加單位、可改名稱、可加圖示） | 客廳溫度、濕度、今日用電度數 |
| `chart` | 畫一個實體**過去 N 小時**的折線圖 | 過去 24 小時的溫度、過去 7 天的體重 |
| `list` | 列出**一組實體**的狀態，可以自己點名，也可以「依條件自動挑」 | 所有插座的功率、所有溫度感應器 |

每張卡片都可以再加一個**連結**（例如連去 HA 的某個頁面），和一段小說明。

**不能做的（刻意不做，降低風險）：**

- **不能控制任何東西**：沒有開關、按鈕、呼叫服務。這個儀表板對 HA 只做「讀取」。
- 不能顯示 HA 以外的資料（資料來源只有你的 HA）。
- 卡片排版是固定的（依宣告順序一張一張排，畫面寬時會並排），不能自訂顏色或位置。

## 2. 開始前的準備

1. **你要有一套能用的 Home Assistant**，而且儀表板所在的電腦連得到它。
2. 在 `config.json` 填好 HA 的連線（做法見主 README 的「需要自己申請的東西 › 1」）：
   - `ha.url`：HA 的網址，例如 `"http://homeassistant.local:8123"`
   - 長期存取權杖：**不要寫在 config.json**，放環境變數 `HA_TOKEN`，或放權限 600 的檔案再用 `ha.token_file` 指過去。
3. 在 `config.json` 裡有一個叫 `custom` 的區塊，卡片就寫在它的 `cards` 清單裡。`config.example.json` 已經附了三張示範卡，可以先拿來改。

寫完後**重新啟動伺服器**（`custom.cache_seconds` 預設 30 秒，所以資料不是即時的，見第 7 節），再打開儀表板的「自訂」分頁。

## 3. 怎麼找到實體 ID

**實體 ID** 是 HA 給每個東西的名字，格式是「類型.名稱」，例如：

- `sensor.living_room_temperature`（客廳溫度感應器）
- `sensor.house_power`（全屋功率）
- `switch.desk_plug`（桌燈插座的開關；只能讀它是開還是關，不能控制）

規則：**全部小寫英文字母、數字、底線**，中間一個點。不能有空格、不能有大寫、不能有中文。

### 方法一：開發者工具（最準）

1. 打開 HA 網頁，左側選單點「**開發者工具**」。
2. 點上方的「**狀態**」分頁。
3. 在「實體」欄位輸入關鍵字（例如 `temperature`、`power`、`steps`）。
4. 下面的表格第一欄就是實體 ID，旁邊會顯示目前的**狀態**與**屬性**。
   - 看「屬性」裡的 `unit_of_measurement`：這就是單位（`°C`、`W`、`kWh`、`%`…）。
   - 看「屬性」裡的 `friendly_name`：這是 HA 顯示給你看的名稱，卡片預設會用它。

### 方法二：從裝置或實體頁面

1. 「設定」→「裝置與服務」→ 點「實體」分頁，搜尋你要的東西。
2. 點進去 → 右上角的齒輪（設定）→ 會看到「**實體 ID**」欄位，複製即可。

### 確認這個實體「有數值」

- **value 卡**：任何實體都能顯示，非數字（例如 `on`／`off`）就原樣顯示文字。
- **chart 卡**：要畫折線圖，這個實體的狀態必須是**數字**（溫度、功率、步數…）。`on`／`off` 這種文字不會畫出圖。
  在 HA 的實體頁面能看到歷史圖，就代表有資料可畫。
- 注意 HA 預設只保留約 **10 天**歷史，所以 chart 的 `hours` 設再大也看不到更早的資料。

### 小陷阱

- 有時同一個東西會出現 `sensor.xxx` 與 `sensor.xxx_2`，那是 HA 為了避免名稱重複自動加的，請挑**正在更新**的那一個（看狀態旁的時間）。
- 複製出來的實體 ID 如果有大寫或空格，通常是複製到了友善名稱，不是 ID。

## 4. 設定檔怎麼改（JSON 的基本規則）

`config.json` 是 **JSON** 格式，像這樣：

```json
{
 "custom": {
  "title": "自訂",
  "cards": [
   { 第一張卡 },
   { 第二張卡 }
  ]
 }
}
```

最容易出錯的幾條規則：

1. **文字一定要用「半形雙引號」** `"…"` 包起來。數字不要加引號（`24` 不是 `"24"`）。
2. **同一層的項目之間要用逗號分隔，最後一個後面不能有逗號。** 這是最常見的錯誤。
   ```json
   {"type": "value", "title": "溫度"}     ← 正確（最後沒有逗號）
   {"type": "value", "title": "溫度",}    ← 錯誤（多了一個逗號）
   ```
3. 括號要成對：`{ }`（一組設定）、`[ ]`（一串清單）。
4. JSON **不能寫註解**。想留備註的話，在任何一組設定裡加一個以底線開頭的欄位，例如 `"_說明": "這是客廳"`，程式會自動忽略它。
5. 用「純文字編輯器」改（記事本、VS Code 都行），不要用會自動把引號變成彎引號的軟體（例如 Word）。

**改完先檢查語法**（在專案資料夾執行；沒有錯誤訊息、印出整份內容就是語法正確）：

```bash
python3 -m json.tool config.json
```

## 5. 三種卡片：value、chart、list

### 通用欄位（三種卡片都能用）

| 欄位 | 必填？ | 說明 |
|---|---|---|
| `type` | 必填 | 卡片類型：`"value"`、`"chart"` 或 `"list"` |
| `title` | 必填 | 卡片標題，1～40 個字 |
| `icon` | 選填 | 標題前面的小圖示，通常放一個 emoji，例如 `"🌡️"`（最多 16 字） |
| `note` | 選填 | 標題下面的一小段說明文字（最多 200 字） |
| `link` | 選填 | 卡片底下的「開啟連結」，只能是 `http://` 或 `https://` 開頭的網址（例如 HA 的某個頁面）。會在新分頁開啟 |

### 實體的寫法（value 與 list 的 `entities` 用）

最簡單：直接寫實體 ID 當文字。要改名稱或單位時，寫成一組設定：

```json
"entities": [
  "sensor.living_room_temperature",
  {"id": "sensor.living_room_humidity", "name": "客廳濕度", "unit": "%", "decimals": 0, "icon": "💧"}
]
```

| 欄位 | 說明 |
|---|---|
| `id` | **必填**。實體 ID |
| `name` | 顯示名稱（最多 40 字）。不寫就用 HA 的 `friendly_name`，再沒有就顯示實體 ID |
| `unit` | 單位（最多 12 字）。不寫就用 HA 的單位 |
| `decimals` | 小數幾位（0～6）。不寫就自動（最多兩位，尾端的 0 會去掉）。只對數字有效 |
| `icon` | 名稱前面的圖示 |

---

### 5.1 value 卡：顯示目前值

| 欄位 | 必填？ | 說明 |
|---|---|---|
| `entities` | 必填 | 實體清單，**1～12 個**。每個實體顯示成一個方塊（名稱＋大字數值＋單位＋更新時間） |

完整範例：

```json
{
  "type": "value",
  "title": "客廳環境",
  "icon": "🌡️",
  "note": "每 30 秒更新一次",
  "entities": [
    {"id": "sensor.living_room_temperature", "name": "溫度", "decimals": 1},
    {"id": "sensor.living_room_humidity", "name": "濕度", "decimals": 0}
  ],
  "link": "http://homeassistant.local:8123/lovelace/0"
}
```

畫面上：

- 實體在 HA 裡**不存在**（ID 打錯）→ 方塊顯示「**找不到**」。
- 實體是 `unavailable`（裝置離線）→ 顯示「**無法使用**」。
- 滑鼠停在方塊上會顯示實體 ID，方便對照。

---

### 5.2 chart 卡：過去 N 小時折線圖

| 欄位 | 必填？ | 說明 |
|---|---|---|
| `entity` | 必填 | **一個**實體 ID（注意這裡是 `entity`，單數，不是清單） |
| `hours` | 選填 | 回看幾小時，**1～168**（最多 7 天），預設 24。要是整數，不要加引號 |
| `name` | 選填 | 圖上方的名稱 |
| `unit` | 選填 | 單位（不寫就用 HA 的） |
| `decimals` | 選填 | 最新／最低／最高值的小數位數（0～6） |

完整範例：

```json
{
  "type": "chart",
  "title": "客廳溫度（過去 24 小時）",
  "entity": "sensor.living_room_temperature",
  "hours": 24,
  "unit": "°C",
  "decimals": 1
}
```

畫面上：

- 折線圖左邊標最高與最低值、下面標起訖時間，最後一點用黃色圓點標出；下方文字寫「最新／最低／最高／共幾筆」。
- 這段時間沒有足夠的**數字**資料（例如實體是 `on`／`off`），會顯示「這段時間沒有足夠的數值資料」。
- 資料點太多時（超過 200 個），畫面上會縮減點數以便繪圖：**每一段保留最低與最高那兩點、並保留最後一點的原值**，所以尖峰、谷底與最新值不會被平均掉；下方的「最新／最低／最高」永遠是用原始資料算的。文字會告訴你有縮點。
- 實體不存在 → 這張卡顯示紅色錯誤「在 Home Assistant 找不到這個實體」，**不影響其他卡片**。

---

### 5.3 list 卡：一組實體的列表

list 卡有**兩種寫法，二選一**（不能都寫、也不能都不寫）：

**寫法 A：自己點名** — 用 `entities` 列出來（最多 50 個），照你寫的順序顯示（除非加 `sort`）。

```json
{
  "type": "list",
  "title": "三個插座",
  "entities": ["sensor.plug_fridge_power", "sensor.plug_washer_power", {"id": "sensor.plug_tv_power", "name": "電視"}]
}
```

**寫法 B：依條件自動挑** — 用 `filter` 告訴程式「幫我找出符合這些條件的所有實體」。

| `filter` 裡的欄位 | 說明 |
|---|---|
| `domain` | 實體類型，也就是實體 ID 點號前面那段，例如 `"sensor"`、`"switch"`、`"binary_sensor"` |
| `unit` | 單位，例如 `"W"`、`"°C"`、`"kWh"`（要和 HA 裡的單位完全一樣，注意大小寫） |
| `contains` | 文字清單，實體 ID 或名稱**要同時包含全部**這些字（不分大小寫）。例如 `["plug", "power"]` |
| `exclude` | 文字清單，只要實體 ID 或名稱**包含其中任何一個**就排除（不分大小寫）。例如 `["nominal", "額定"]` |

`domain`、`unit`、`contains` **至少要填一個**（否則會把 HA 裡幾百個實體全部列出來）。

其他欄位（兩種寫法都能用）：

| 欄位 | 說明 |
|---|---|
| `limit` | 最多列幾行，**1～50**，預設 30 |
| `sort` | 排序：`"value_desc"`（數值由大到小）、`"value_asc"`（由小到大）、`"name"`（依名稱）。自動挑（寫法 B）時不寫的話：有數字就由大到小，否則依名稱；點名（寫法 A）時不寫就照你寫的順序 |

完整範例（列出所有功率感應器，排除 UPS 的額定功率，最多 20 行）：

```json
{
  "type": "list",
  "title": "各插座目前功率",
  "note": "列出所有單位為 W 的感應器，由大到小排",
  "filter": {"domain": "sensor", "unit": "W", "exclude": ["nominal", "額定"]},
  "sort": "value_desc",
  "limit": 20
}
```

畫面上：符合的實體比 `limit` 多時，會寫「共 N 個符合，只列前 M 個」。沒有任何符合時顯示「沒有符合條件的實體」。
無法使用（離線）的實體會排在最後面。

## 6. 三組現成範例

三組範例都放在專案的 `docs/examples/` 資料夾，是完整可用的 `custom` 區塊。使用方法：

1. 打開範例檔（用文字編輯器）。
2. 把裡面的 `sensor.your_…` **全部換成你自己的實體 ID**（第 3 節教你怎麼找）。不想要的卡片整張刪掉。
3. 把 `"custom": { … }` 那一整段，**取代** `config.json` 裡原本的 `custom` 區塊。
4. 檢查語法（`python3 -m json.tool config.json`），重新啟動，開「自訂」分頁。

### 範例一：每日步數＋體重

檔案：`docs/examples/combo1-steps-weight.json`

- 一張 value 卡：今天的步數與最新體重。
- 兩張 chart 卡：過去 7 天的步數與體重。
- 需要：手機的 HA App 提供的步數感應器（實體名稱依手機而定，常見像 `sensor.你的手機_steps`）、體重感應器（智慧體重計的整合，或你自己建的 `input_number`）。
- 小提醒：手機計步器的步數通常是「當天累計」，每天歸零，所以折線圖會呈鋸齒狀，正常。

### 範例二：全屋用電＋插座列表

檔案：`docs/examples/combo2-power.json`

- 一張 value 卡：全屋目前功率（W）與今日用電度數（kWh），附連去 HA 能源頁的連結。
- 一張 chart 卡：全屋功率過去 24 小時。
- 一張 list 卡：自動列出所有單位是 W 的感應器（各插座目前功率），由大到小。
- 需要：智慧電表或電力監測插座；list 卡不用你一個一個填實體，會自動找。

### 範例三：溫濕度

檔案：`docs/examples/combo3-climate.json`

- 一張 value 卡：客廳與臥室的溫度、濕度（4 個方塊）。
- 兩張 chart 卡：客廳溫度、濕度過去 24 小時。
- 一張 list 卡：自動列出所有名稱或 ID 含 `temperature` 的感應器。

> 三個範例可以**合併**：把各個範例 `cards` 裡的卡片，複製進同一個 `cards` 清單即可（記得卡片之間要有逗號，總共最多 20 張）。

## 7. 限制與上限

| 項目 | 上限／行為 |
|---|---|
| 卡片數量 | 最多 **20 張** |
| value 卡的實體數 | 最多 **12 個** |
| list 卡 | 自己點名最多 **50 個**；`limit` 最多 **50**（預設 30） |
| chart 卡回看時間 | 最多 **168 小時**（7 天）；HA 本身預設只留約 10 天歷史 |
| chart 畫面點數 | 最多約 200 點（超過會縮點：每段保留最高與最低點、最後一點保留原值） |
| 標題／名稱／說明 | 標題 40 字、名稱 40 字、說明 200 字、單位 12 字、圖示 16 字、連結 300 字 |
| 更新頻率 | 伺服器端快取 `custom.cache_seconds` 秒（預設 30，可設 10～3600）。不論多少人同時開頁面，HA 在這段時間內只被問一次。頁面開著時每 60 秒自動重讀，也可按「重新整理」（重新整理仍可能拿到快取內的資料） |
| 只讀 | **沒有任何寫入或控制功能**，也不會有；卡片只會讀取 HA |
| 資料範圍 | 只顯示 HA 回傳的資料；實體不存在、離線都只會在該卡片或該實體上標示，不會影響其他卡片 |
| 連結 | 只能是 `http://` 或 `https://` |

## 8. 常見錯誤訊息怎麼解

### 啟動時出現「設定檔有問題：…」

伺服器**不會啟動**，並用中文說是**第幾張卡的哪個欄位**有問題。照訊息改完再啟動即可。

| 訊息（節錄） | 意思與解法 |
|---|---|
| `設定檔 … 不是合法的 JSON：…` | JSON 語法錯誤，最常見是**多一個逗號**或**少一個引號／括號**。用 `python3 -m json.tool config.json` 找出行號（見第 4 節） |
| `custom.cards 的第 2 張卡（「溫度」）的 entities[1].id … 不是正確的實體 ID` | 第 2 張卡的第 1 個實體 ID 格式不對：要小寫英文、數字、底線，中間一個點（見第 3 節） |
| `… 的 type（'gauge'）不認得：只能是 value、chart、list` | 卡片類型打錯，或你想用的類型不存在。本專案只有這三種唯讀卡片；若訊息提到「唯讀」，表示你寫了開關／按鈕之類的控制型別，這是不支援的 |
| `… 有不認得的欄位「entites」（是不是想寫「entities」？）` | 欄位名稱拼錯了，照提示改 |
| `… 的 hours 要在 1～168 之間，目前是 999` | 數字超出範圍 |
| `… 的 hours 要是整數（不要加引號），目前是 '24'` | 數字不要加引號 |
| `… 的 entities 要是至少一個實體的清單` | value 卡的 `entities` 是空的或寫成了單一文字，要用 `[ … ]` 包起來 |
| `… 的 entities 太多（最多 12 個，目前 15）；請拆成兩張卡` | 超過上限 |
| `… 要在 entities（自己列出實體）與 filter（依條件挑）兩種寫法裡擇一` | list 卡要嘛寫 `entities`，要嘛寫 `filter`，不能都寫或都沒寫 |
| `… 的 filter 至少要填 domain、unit、contains 其中一個` | filter 太寬鬆了，補上條件 |
| `… 的 link 只能是 http:// 或 https:// 開頭的網址` | 連結格式不對 |
| `… 的 title 不能空白` / `太長` / `要是文字（用雙引號包起來）` | 標題缺漏或格式錯 |
| `custom.cards 太多張（最多 20 張）` | 卡片超過 20 張 |
| `custom.cache_seconds 要在 10～3600 之間` | 快取秒數超出範圍 |

### 「自訂」分頁顯示「尚未設定：…」

不是故障，是還沒設定好：

| 訊息（節錄） | 解法 |
|---|---|
| `尚未在設定檔 custom.cards 宣告任何卡片` | 還沒寫任何卡片，照第 5、6 節加上 |
| `「自訂」分頁的資料來自 Home Assistant，但尚未設定 ha.url 與權杖` | 補上 `ha.url` 與 HA 權杖（第 2 節） |
| `尚未設定 Home Assistant 權杖` | 設定環境變數 `HA_TOKEN`，或 `ha.token_file` |
| `權杖檔 … 權限太鬆，請執行：chmod 600 …` | 權杖檔權限要只有自己能讀，照訊息執行指令 |

### 分頁或卡片上出現紅色錯誤

| 訊息（節錄） | 意思與解法 |
|---|---|
| `Home Assistant 拒絕這組權杖（401/403）` | 權杖不對、過期，或被刪掉。到 HA 個人資料頁重新建一個長期存取權杖 |
| `連不到 Home Assistant（…）` | `ha.url` 打錯、HA 沒開、或這台電腦連不到它。先用瀏覽器開 `ha.url` 試試 |
| `連線 Home Assistant 逾時（20 秒）` | HA 太慢或網路不通。可調大 `ha.timeout_seconds`（3～60） |
| `Home Assistant 回應了重新導向，為了保護權杖已拒絕跟隨` | `ha.url` 不是最終網址（例如 http 被轉成 https）。改成實際會用的最終網址 |
| `Home Assistant 回傳的資料格式不是預期的…` | HA 回應異常（或中間有代理改了內容）。確認 `ha.url` 指到真正的 HA |
| `在 Home Assistant 找不到這個實體` | （chart 卡）實體 ID 拼錯或已被刪除。回第 3 節確認 |
| 方塊顯示「找不到」 | （value／list 卡）同上 |
| 方塊顯示「無法使用」 | 實體在 HA 裡是 `unavailable`，通常是裝置離線，不是儀表板的問題 |
| 折線圖：`這段時間沒有足夠的數值資料` | 實體不是數字、或這段時間沒有紀錄（HA 只留約 10 天） |

### 「資料好像沒更新」

伺服器端有快取（預設 30 秒），所以資料最多會延遲約 30 秒；調小 `custom.cache_seconds`（最小 10）可以更即時，但會更頻繁地詢問 HA。

## 9. 安全小提醒

- 卡片顯示的就是你 HA 裡的資料。**能打開這個儀表板的人，就看得到你放上來的所有卡片內容**，所以請照主 README 的「安全注意事項」設好存取密語，不要把儀表板開到公開網路。
- 儀表板對 HA 只做讀取（GET），而且連 HA 的權杖都只存在你的環境變數或 600 權限的檔案裡，不會出現在網頁或日誌。
- 長期存取權杖的權限等同建立它的那個 HA 使用者。想降低風險的話，可以為儀表板另外建一個**非管理員**的 HA 使用者，用那個使用者的權杖；並且定期到 HA 個人資料頁檢查、撤銷不再使用的權杖。
